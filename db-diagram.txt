# Prompt Board Database Schema Diagram

## Overview
This diagram represents the complete database schema for Prompt Board, a collaborative prompt management platform. The schema supports user authentication, organization management, prompt storage, categorization, context management, and workflow automation.

## Database Architecture

### Schema Design Principles
- **Multi-tenancy**: Supports both personal and organization-level data
- **Row Level Security (RLS)**: All tables have comprehensive security policies
- **Full-text Search**: Prompts support semantic search capabilities
- **Audit Trail**: Comprehensive created_at/updated_at tracking
- **Data Integrity**: Foreign key constraints and check constraints

## Enums and Types

### user_role (ENUM)
- `admin`: Full organization management permissions
- `member`: Can create and share prompts within organization
- `viewer`: Read-only access to organization prompts

### visibility_type (ENUM)
- `private`: Only visible to the creator
- `team`: Visible to organization members
- `public`: Visible to everyone

## Key Relationships

### Primary Relationships
1. **auth.users** → **profiles** (1:1) - User profile extension
2. **profiles** → **organizations** (M:M via user_organizations) - Team membership
3. **profiles** → **prompts** (1:M) - Prompt ownership
4. **organizations** → **prompts** (1:M) - Organization-scoped prompts
5. **categories** → **prompts** (1:M) - Prompt categorization
6. **contexts** → **prompts** (M:M via context_prompts) - Context associations
7. **workflows** → **workflow_executions** (1:M) - Workflow runs

### Cross-table Constraints
- Categories must belong to either a user OR organization (not both)
- Prompts can be personal or organization-scoped
- Context management is user-specific
- Workflows are user-specific

## Indexes and Performance

## Security Policies (RLS)

### Access Control Patterns
All tables implement Row Level Security with these patterns:

1. **User-owned data**: Users can CRUD their own records
2. **Organization data**: Members can read, admins can write
3. **Visibility-based**: Public/team/private visibility controls
4. **Hierarchical permissions**: Organization roles determine access levels

### Key Policy Functions
- `check_organization_membership(org_id, user_id)`: Validates membership
- `get_user_role_in_organization(org_id, user_id)`: Returns user role
- Organization admins inherit member permissions
- Cross-table policy validation for data integrity

## Functions and Triggers

### Automated Functions
- `handle_new_user()`: Creates profile on user signup
- `create_default_context_for_user()`: Creates default context
- `add_creator_as_admin()`: Adds creator as admin to new orgs
- `update_prompts_tsv()`: Updates full-text search vectors
- `update_updated_at_column()`: Maintains timestamp consistency

### Utility Functions
- `increment_prompt_usage()`: Tracks prompt usage
- `search_prompts()`: Advanced search with filtering
- `get_prompt_stats()`: Organization analytics
- `get_categories_with_stats()`: Category usage statistics
- `validate_category_assignment()`: Ensures valid category access

## Data Integrity

### Constraints
- Foreign key relationships maintain referential integrity
- Check constraints validate enum values and business rules
- Unique constraints prevent duplicate data
- NOT NULL constraints ensure required fields

### Validation
- Email validation through Supabase Auth
- Slug validation for organization names
- Category ownership validation (user XOR organization)
- Prompt visibility validation based on organization membership

This schema supports a comprehensive prompt management platform with enterprise-grade security, performance, and scalability features.
