# Sprint 3: Team Collaboration & Sharing System (Weeks 5-6)

## Sprint Goal
Implement team collaboration features including prompt sharing, permissions management, commenting system, and real-time collaboration capabilities.

## User Stories

### Epic: Collaboration & Sharing
**Story 3.1:** Prompt Sharing & Permissions
- As a user, I want to share prompts with my team so that we can collaborate on prompt development
- As a user, I want to control who can view and edit my prompts so that I can manage access appropriately
- As a team lead, I want to manage team member permissions so that I can control collaboration levels

**Story 3.2:** Team Management
- As an admin, I want to invite team members to my organization so that we can work together
- As an admin, I want to assign roles to team members so that I can control access levels
- As a team member, I want to see who else is in my organization so that I know who I can collaborate with

**Story 3.3:** Commenting & Feedback System
- As a user, I want to comment on team prompts so that I can provide feedback and suggestions
- As a prompt owner, I want to see comments on my prompts so that I can improve them based on feedback
- As a team member, I want to be notified of comments on prompts I'm involved with

**Story 3.4:** Real-time Collaboration
- As a user, I want to see when others are viewing or editing shared prompts so that we can avoid conflicts
- As a team member, I want to see updates to shared prompts in real-time so that I'm always working with the latest version

## Acceptance Criteria

### Sharing & Permissions System
- [ ] Users can set prompt visibility to Private, Team, or Public
- [ ] Team prompts are visible to all organization members
- [ ] Public prompts are discoverable by all platform users
- [ ] Users can change sharing settings on existing prompts
- [ ] Permission changes take effect immediately across all users
- [ ] Shared prompts display owner information and sharing status

### Team Management
- [ ] Admins can invite users via email invitation
- [ ] Invited users receive email with signup/join link
- [ ] Users can accept invitations and join organizations
- [ ] Admins can assign roles: Admin, Member, Viewer
- [ ] Role permissions are enforced throughout the application
- [ ] Team member list shows roles and last activity

### Role-Based Access Control
- [ ] **Admin**: Full access to organization, can invite/remove users, manage all prompts
- [ ] **Member**: Can create/edit own prompts, view/comment on team prompts, cannot manage users
- [ ] **Viewer**: Can view team prompts and add comments, cannot create or edit prompts
- [ ] Role changes are reflected immediately without requiring re-login

### Commenting System
- [ ] Users can add comments to any prompt they have access to
- [ ] Comments display with author name, timestamp, and content
- [ ] Comment authors can edit and delete their own comments
- [ ] Prompt owners can delete any comments on their prompts
- [ ] Comments are ordered chronologically
- [ ] Real-time comment updates across all viewers

### Real-time Features
- [ ] Live presence indicators show who is currently viewing prompts
- [ ] Real-time comment notifications appear without page refresh
- [ ] Prompt updates propagate immediately to all viewers
- [ ] Connection status indicator shows real-time connectivity
- [ ] Graceful handling of network disconnections

### Notifications
- [ ] In-app notifications for comments on user's prompts
- [ ] Email notifications for important team activities (configurable)
- [ ] Notification center shows recent activity
- [ ] Users can mark notifications as read
- [ ] Notification preferences can be customized

## Implementation Plan

### Phase 1: Database Schema & Permissions (Day 1-2)
1. **Enhanced Database Schema**
   ```sql
   -- Enhanced user_organizations with roles
   ALTER TABLE user_organizations 
   ADD COLUMN role TEXT DEFAULT 'member' 
   CHECK (role IN ('admin', 'member', 'viewer'));
   
   -- Comments table
   CREATE TABLE comments (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     prompt_id UUID REFERENCES prompts(id) ON DELETE CASCADE,
     user_id UUID REFERENCES auth.users(id),
     content TEXT NOT NULL,
     created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
     updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   );
   
   -- Invitations table
   CREATE TABLE invitations (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     email TEXT NOT NULL,
     organization_id UUID REFERENCES organizations(id),
     role TEXT DEFAULT 'member',
     invited_by UUID REFERENCES auth.users(id),
     token TEXT UNIQUE NOT NULL,
     expires_at TIMESTAMP WITH TIME ZONE,
     accepted_at TIMESTAMP WITH TIME ZONE,
     created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   );
   
   -- Notifications table
   CREATE TABLE notifications (
     id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
     user_id UUID REFERENCES auth.users(id),
     type TEXT NOT NULL,
     title TEXT NOT NULL,
     content TEXT,
     related_id UUID,
     read_at TIMESTAMP WITH TIME ZONE,
     created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
   );
   ```

2. **Advanced RLS Policies**
   ```sql
   -- Prompt visibility policies
   CREATE POLICY "Users can view prompts based on visibility" ON prompts
     FOR SELECT USING (
       visibility = 'public' OR
       user_id = auth.uid() OR
       (visibility = 'team' AND organization_id IN (
         SELECT organization_id FROM user_organizations 
         WHERE user_id = auth.uid()
       ))
     );
   
   -- Comment access policies
   CREATE POLICY "Users can comment on accessible prompts" ON comments
     FOR INSERT WITH CHECK (
       prompt_id IN (SELECT id FROM prompts WHERE /* user has access */)
     );
   ```

2. **Real-time Comment Updates**
   ```typescript
   // useComments.ts
   export const useComments = (promptId: string) => {
     const queryClient = useQueryClient();
     
     useEffect(() => {
       const channel = supabase
         .channel(`comments:${promptId}`)
         .on('postgres_changes',
           { event: '*', schema: 'public', table: 'comments', filter: `prompt_id=eq.${promptId}` },
           (payload) => {
             queryClient.setQueryData(['comments', promptId], (old: Comment[]) => 
               updateCommentsCache(old, payload)
             );
           }
         )
         .subscribe();
       
       return () => supabase.removeChannel(channel);
     }, [promptId]);
   };
   ```

### Phase 5: Real-time Features & Notifications (Day 9-10)
1. **Presence System**
   ```typescript
   // usePresence.ts
   export const usePresence = (promptId: string) => {
     const [users, setUsers] = useState<PresenceUser[]>([]);
     
     useEffect(() => {
       const channel = supabase.channel(`presence:${promptId}`, {
         config: { presence: { key: currentUser.id } }
       });
       
       channel
         .on('presence', { event: 'sync' }, () => {
           const presenceState = channel.presenceState();
           setUsers(Object.values(presenceState).flat());
         })
         .subscribe(async (status) => {
           if (status === 'SUBSCRIBED') {
             await channel.track({
               user_id: currentUser.id,
               name: currentUser.name,
               avatar_url: currentUser.avatar_url,
               viewing_at: new Date().toISOString()
             });
           }
         });
       
       return () => supabase.removeChannel(channel);
     }, [promptId]);
   };
   ```
